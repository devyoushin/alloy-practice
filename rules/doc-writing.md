# 문서 작성 규칙 — alloy-practice

## 기본 원칙
1. 모든 문서는 한국어로 작성하되, 기술 용어(River, Component, Pipeline, Alloy 등)는 영어 그대로 사용
2. 제목은 `# [주제] — Grafana Alloy [문서유형]` 형식으로 통일
3. 문서 상단에 작성일, 작성자, 검토자 메타데이터 포함
4. 코드 블록에는 반드시 언어 지정 (```river, ```yaml, ```bash)
5. River 설정은 컴포넌트 블록 단위로 구분하고 주석 필수

## 문서 구조
- **개요**: 목적과 수집 신호 범위 (3-5문장)
- **파이프라인 구성**: 컴포넌트 흐름 다이어그램
- **River 설정**: 핵심 설정 블록 설명
- **운영**: 체크리스트 및 명령어
- **트러블슈팅**: 증상-원인-해결 테이블

## River 설정 문서화 규칙
- 각 컴포넌트 블록 위에 목적 주석 필수
- 컴포넌트 참조(`component.output`) 화살표로 연결 표현
- `export` 블록은 반드시 사용처 설명
- 민감 값은 `env()` 또는 K8s Secret 참조

## 금지 사항
- API 키, 토큰 River 파일에 하드코딩 금지
- 프로덕션 엔드포인트 문서에 직접 포함 금지
- 검증되지 않은 River 설정 문서화 금지
